## О себе

Инженер с фокусом на **DevOps, Linux и platform engineering**. Прохожу путь от системного уровня (C, POSIX, сети) до production-практик: **мониторинг, логи, автоматизация, hardening и эксплуатация сервисов**.

Работаю в парадигме **SRE**: метрики вместо догадок, идемпотентные скрипты вместо ручных runbook'ов, документация рядом с кодом. Собираю стек под **Arch Linux**, но проектирую решения переносимыми — Bash, контейнеры, стандартные протоколы observability.

```text
┌─────────────────────────────────────────────────────────────────┐
│  Provision → Configure → Observe → Automate → Harden → Iterate  │
└─────────────────────────────────────────────────────────────────┘
```

## Ключевые проекты

### [`linux-devops`](https://github.com/putniikiis/linux-devops) — DevOps Portfolio

> Production-oriented практики: от bare-metal до observability stack.

| Модуль | Что решает | Стек |
|--------|------------|------|
| **linux-admin-basics** | OS provisioning, users, SSH, cron, disks, logging | Ubuntu, systemd, docs |
| **bash-system-monitor** | Сбор метрик хоста, цветной вывод, статистика FS | Bash, awk, ANSI |
| **observability-stack** | Генерация логов, анализ, **Prometheus + Grafana** | GoAccess, custom metrics |

<br/>

### [`c-libraries`](https://github.com/putniikiis/c-libraries) — Systems Engineering

> Низкоуровневый фундамент: понимание того, *под капотом* у инфраструктурных утилит.

| Проект | Суть | Навык |
|--------|------|-------|
| **string-library** | Аналог `string.h`, `sprintf`/`sscanf` | память, парсинг, 25+ unit-тестов |
| **cat-grep-clone** | GNU-совместимые `cat` / `grep` | CLI, `getopt_long`, POSIX regex |
| **decimal-arithmetic** | 128-bit decimal арифметика | битовые операции, overflow |

## Инженерные принципы

```
✓  Everything as code        — скрипты, конфиги, документация в git
✓  Observable by default     — метрики и логи до инцидента, не после
✓  Idempotent operations     — повторный запуск без побочных эффектов
✓  Least privilege           — пользователи, ключи, firewall rules
✓  Document the why          — README рядом с каждым модулем
```
